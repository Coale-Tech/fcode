# frappe-ui Tailwind Tokens (v1)

Adapted in part from frappe/frappe-ui (MIT): `skills/frappe-ui/TOKENS.md`, `spec/foundations.md`.

Every class documented here is emitted by frappe-ui's Tailwind v3 preset —
nothing here is hand-authored CSS. The preset is a **separate implementation**
of the "espresso" token vocabulary from [Desk's SCSS](espresso-design-system.md);
same names, generated by different code, from a different source of truth
(Figma, not hand-maintained SCSS). See
[espresso-design-system.md § Espresso (Desk) vs frappe-ui (Vue apps)](espresso-design-system.md#espresso-desk-vs-frappe-ui-vue-apps)
for the split.

Version: **v1** (`1.0.0-beta.29`, commit `f730c18`). Claims below apply to this
version unless tagged `(0.1.261 baseline)`. Always check `frontend/package.json`
for the pinned version before relying on a v1-only class.

## Setup

```js
// tailwind.config.js
import frappeUIPreset from 'frappe-ui/tailwind'

export default {
  presets: [frappeUIPreset],
  content: [
    './index.html',
    './src/**/*.{vue,js,ts,jsx,tsx}',
    './node_modules/frappe-ui/src/**/*.{vue,js,ts}',
  ],
}
```

```css
/* main CSS entry */
@import 'frappe-ui/style.css';
```

`frappe-ui/tailwind` resolves to `tailwind/index.js` → `tailwind/preset.js`
(`package.json` `exports["./tailwind"]`). The preset composes four Tailwind
plugins: `@tailwindcss/forms`, `@tailwindcss/typography`, frappe-ui's own theme
plugin (`tailwind/plugin.js`), and `lucideIconsPlugin` (`tailwind/lucideIconsPlugin.js`).
This same subpath existed at the 0.1.261 baseline; only very old pre-exports-map
apps (e.g. `apps/hrms/frontend` pinned at `0.1.105`) use the deep import
`frappe-ui/src/tailwind/preset` instead — don't copy that into new code.

`darkMode: ['selector', '[data-theme="dark"]']` — dark mode is opt-in per
element via the `dark:` variant **and** globally driven by setting
`data-theme="dark"` on `<html>` (`tailwind/preset.js`).

## Color tokens

### Semantic families (use these)

Three axes, each `bg-`/`text-`/`border-` (etc.) prefixed, generated by
`colorPalette.js#generateSemanticColors` from `colors.json`'s
`themedVariables.light` map (`tailwind/plugin.js` wires them into Tailwind's
`textColor`/`backgroundColor`/`borderColor`/`ringColor`/`divideColor`/`fill`/`stroke`/
`gradientColorStops`/`placeholderColor` theme extensions):

| Prefix | Tailwind utility | CSS var backing | Notes |
|---|---|---|---|
| `ink` | `text-ink-*`, `placeholder-ink-*`, `fill-ink-*`, `stroke-ink-*` | `--ink-*` | foreground / text / icons |
| `surface` | `bg-surface-*` | `--surface-*` | backgrounds / fills |
| `surface-alpha` | `bg-surface-alpha-*` | `--surface-alpha-*` | translucent backgrounds |
| `outline` | `border-outline-*`, `ring-outline-*`, `divide-outline-*` | `--outline-*` | borders / rings / dividers |
| `outline-alpha` | `border-outline-alpha-*`, `ring-outline-alpha-*`, `divide-outline-alpha-*` | `--outline-alpha-*` | translucent borders |

The exact key set per family (`base`, `gray-1..N`, `red-1..N`, …, `sidebar`,
`elevation-1..3`, …) is whatever `colors.json`'s `themedVariables.light`
declares — read `tailwind/colors.json` for the authoritative list rather than
assuming a fixed range; espresso v2 changed several of these (see
[frappe-ui-tokens-v2-migration.md](frappe-ui-tokens-v2-migration.md)).

Each semantic value is generated as
`color-mix(in srgb, var(--{category}-{name}, {lightValue}) calc(<alpha-value> * 100%), transparent)`
(`colorPalette.js#generateSemanticColors`) — so opacity modifiers
(`bg-surface-gray-2/50`) work, and the value follows whichever CSS var is
currently in scope (flipped under `[data-theme="dark"]`).

### Raw palette (avoid in app code)

`colorPalette.js#generateColorPalette` also exposes every raw shade as plain
Tailwind colors: `gray`, `blue`, `green`, `red`, `orange`, `yellow`, `teal`,
`violet`, `cyan`, `amber`, `pink`, `purple`, each with a `dark-` prefixed
counterpart (`dark-gray`, `dark-blue`, …) from `colorsData.darkMode`, plus
`white-overlay-*` / `black-overlay-*` alpha ramps. Solid `oklch(...)` values
get an injected `<alpha-value>` placeholder (`withAlphaPlaceholder`) so
`bg-blue-900/30` opacity modifiers work on them too. These raw classes
(`bg-blue-500`, `text-gray-900`) don't track dark mode — prefer the semantic
families above.

### CSS custom properties

Every semantic + raw color also lands on `:root` / `[data-theme="dark"]` as a
plain CSS var (`--ink-gray-9`, `--surface-white`, `--gray-500`, …), generated
by `colorPalette.js#generateCSSVariables` and registered via `addBase` in
`tailwind/plugin.js`. Use these directly in `<style>` blocks or inline styles
when a Tailwind utility doesn't exist for what you need.

## Typography

`fontFamily.sans` is extended with `InterVar` (`html { font-family: InterVar, ... }`,
`tailwind/plugin.js#globalStyles`); `font-optical-sizing: auto` and
`fontVariationSettings: "'opsz' 24, 'cv11' 1"` are set globally on
`html, body, button, p, span, div`.

### Size scale

`text-{size}` / `text-p-{size}` utilities, generated by `buildFontSize()`
(`tailwind/plugin.js`, reading `tailwind/generated/typography.json`). `text-p-*`
uses the same `font-size` but the looser paragraph `lineHeight`/`letterSpacing`.
`fontWeight` on every entry defaults to **420** (the deliberately-heavier
InterVar "regular"), not 400.

| Size | px | `text-{size}` line-height | `text-p-{size}` line-height |
|---|---|---|---|
| `tiny` | 11 | 1.15 (+ `text-transform: uppercase`) | 1.15 |
| `2xs` | 11 | 1.15 | 1.6 |
| `xs` | 12 | 1.15 | 1.6 |
| `sm` | 13 | 1.15 | 1.5 |
| `base` | 14 | 1.15 | 1.5 |
| `md` | 15 | 1.15 | 1.5 |
| `lg` | 16 | 1.15 | 1.5 |
| `xl` | 17 | 1.15 | 1.5 |
| `2xl` | 18 | 1.15 | 1.5 |
| `3xl` | 20 | 1.15 | 1.48 |
| `4xl` | 24 | 1.15 | 1.4 |
| `5xl` | 26 | 1.6 | — |
| `6xl` | 28 | 1.6 | — |
| `7xl` | 32 | 1.6 | — |
| `8xl` | 40 | 1.4 | — |
| `9xl` | 44 | 1.4 | — |
| `10xl` | 48 | 1.4 | — |
| `11xl` | 52 | 1.4 | — |
| `12xl` | 56 | 1.4 | — |
| `13xl` | 64 | 1.3 | — |
| `14xl` | 72 | 1.3 | — |
| `15xl` | 80 | 1.2 | — |
| `16xl` | 88 | 1.2 | — |

(`text-p-*` only exists for sizes with a `paragraph` entry in
`typography.json` — `tiny` through `4xl`; larger display sizes have no
paragraph variant.) `tiny` is the only size with `text-transform: uppercase`
baked in (`textTransform` map).

### Weighted style classes — `text-{size}-{weight}` / `text-p-{size}-{weight}`

Figma models typography as **named styles** where each weight has its own
letter-spacing (medium is tracked tighter than regular at the same size) —
`text-base font-medium` alone doesn't reproduce this. `buildTextStyleUtilities()`
(`tailwind/plugin.js`) emits one component class per confirmed `(size, weight)`
pair from `typography.json`'s `tracking.text` / `tracking.paragraph` maps, for
`WEIGHT_VARIANTS = ['medium', 'semibold', 'bold', 'black']` (regular is the
bare `text-{size}` utility — no `-regular` suffix class exists). Confirmed
examples (`spec/adr/0007-typography-style-utilities.md`):

| Class | font-size | line-height | weight | letter-spacing |
|---|---|---|---|---|
| `text-base-medium` | 14px | 16px | 500 | 0.015em |
| `text-md-medium` | 15px | 17px | 500 | 0.015em |
| `text-lg-medium` | 16px | 18px | 500 | 0.015em |

Not every size has every weight variant generated — only pairs present in the
`tracking` JSON. Check `tailwind/generated/typography.json` `tracking.text.*` /
`tracking.paragraph.*` for the full, current set rather than assuming
coverage; migrating `text-{size} font-medium` → `text-{size}-medium` is
opt-in per component.

### Component sizes vs. text sizes

`spec/foundations.md` records that Figma espresso v2 only defines component
**sizes** `sm`/`md`/`lg` (Button etc.); `xs`, `xl`, `2xl` component sizes are
code-only extensions with no Figma reference. Don't confuse these with the
*text* size scale above, which is unrelated and much larger.

## Radius

`buildRadiusConfig()` (`tailwind/plugin.js`) wires `tailwind/generated/radius.json`
into `borderRadius`, and also emits every entry as a real `--radius-{n}` CSS
variable (`generateRadiusVariables`) so `rounded-4` and `var(--radius-4)` stay
in sync.

| Class | px | Status |
|---|---|---|
| `rounded-0` | 0 | canonical |
| `rounded-1` | 4 | canonical |
| `rounded-2` | 5 | canonical |
| `rounded-3` | 6 | canonical |
| `rounded-4` | 8 | canonical |
| `rounded-5` | 10 | canonical |
| `rounded-6` | 12 | canonical |
| `rounded-7` | 16 | canonical |
| `rounded-8` | 20 | canonical |
| `rounded-9` | 999 | canonical |
| `rounded-full` | 9999 | canonical (semantic, off-scale) |
| `rounded-none` | 0 | canonical (semantic alias of `rounded-0`) |
| `rounded-sm` | 4 | **deprecated** → `rounded-1` |
| `rounded` / `rounded-DEFAULT` | 8 | **deprecated** → `rounded-4` |
| `rounded-md` | 10 | **deprecated** → `rounded-5` |
| `rounded-lg` | 12 | **deprecated** → `rounded-6` |
| `rounded-xl` | 16 | **deprecated** → `rounded-7` |
| `rounded-2xl` | 20 | **deprecated** → `rounded-8` |

Per `spec/adr/0006-numbered-radius-tokens.md`, the
numbered scale is canonical for **new code**; the named aliases remain in
`radius.json` (so existing apps don't break) but are flagged for migration and
may be removed in a future breaking release. `(0.1.261 baseline)`: only the
named aliases exist (`sm`/`DEFAULT`/`md`/`lg`/`xl`/`2xl`/`full`/`none`) at the
same pixel values — no numbered scale, no `rounded-9`.

## Shadow

```js
boxShadow: {
  none: 'none',
  sm: 'var(--elevation-sm)',
  base: 'var(--elevation-base)',
  DEFAULT: 'var(--elevation-base)',
  md: 'var(--elevation-md)',
  lg: 'var(--elevation-lg)',
  xl: 'var(--elevation-xl)',
  '2xl': 'var(--elevation-2xl)',
  status: 'var(--elevation-status)',
}
```

`shadow-{sm,base,md,lg,xl,2xl}` / bare `shadow` (`tailwind/plugin.js`). Values
are CSS vars from `--elevation-*`, generated from `tailwind/generated/effects.json`
`elevation.light`/`elevation.dark` (`colorPalette.js#generateEffectVariables`) —
elevation **does** re-theme in dark mode (heavier, more opaque shadows), unlike
the focus rings below which share Figma's `light/*` values by design.
`shadow-status` is a fixed `0px 0px 0px 1.5px #ffffff` ring used for status
dots, theme-independent.

## Focus ring

Global default — every focusable element gets a ring automatically, no
opt-in class needed:

```css
:focus-visible {
  outline: var(--focus-outline-default); /* 2px solid #c9c9c9e5 light, 3px solid #464646cc dark */
  outline-offset: 0px;
}
```

Implemented as `outline`, not `box-shadow`, specifically so it never collides
with `shadow-*`/`ring-*` utilities on the same element and survives
forced-colors mode (`spec/adr/0005-focus-ring-2px.md`). `.focus-ring{-red,-green,-amber,-blue,-violet}`
component classes (`buildFocusRingUtilities()`, keyed off `effectsData.focus.light`)
exist for **themed overrides** (`focus-visible:focus-ring-red`) and non-focus
states (`data-[state=open]:focus-ring`). Suppress the default with
`focus-visible:outline-none`; never manually add `focus-visible:ring-2` —
that's 0.1.x-era drift, not the current pattern.

## Spacing

The stock Tailwind scale has gaps above `12` (`13`, `15`, `17`, `18`, `19`,
`21`…). `tailwind/preset.js` fills **every** integer `1`–`64` at the
canonical `0.25rem` step (`h-17`, `size-41`, … all compile). `tailwind/plugin.js`
additionally extends `spacing` with half-steps `4.5`…`15.5` (`1.125rem`…`3.875rem`)
and adds one-off extras: `width` gets `3.5` (`0.875rem`), `112` (`28rem`), and
`wizard` (`650px`, used by the multi-step form-wizard layout); `height` gets
`3.5`; `minWidth` gets `40` (`10rem`) and `50` (`18rem`); `maxHeight` gets `52`
(`13rem`).

## Icons — `lucide-{name}`

`lucideIconsPlugin` (`tailwind/lucideIconsPlugin.js`, built on the generic
`iconPackPlugin` in `tailwind/iconPackPlugin.js`) exposes every SVG in
`lucide-static`'s icon set as a `lucide-{name}` utility class via
`matchComponents` — a block-level square that masks the SVG with the current
text color:

```html
<span class="lucide-menu size-4 text-ink-gray-6" />
```

Size with `size-*` (or `w-*`/`h-*`), tint with `text-*`; there is no separate
`fill`/`stroke` prop because the icon is a CSS mask, not an inline `<svg>`.
Lucide ships every icon at `stroke-width="2"`; frappe-ui's plugin instance
normalizes it to `1.5` for a lighter look (`normalizeStrokeWidth: 1.5` in
`lucideIconsPlugin.js`) — no `defaultColor`, so icons inherit `currentColor`
like a native `stroke="currentColor"` SVG would. `iconPackPlugin` is a
reusable factory (any flat directory of named SVGs can be registered this
way); frappe-ui only instantiates it for lucide today. This is the v1 icon
mechanism — the top-level `<FeatherIcon>` Vue component is deprecated.
JIT purges unused entries, so registering the whole pack costs nothing in
generated CSS beyond what's actually referenced in `content`.

## Prose / rich text

`typography: (theme) => ({ DEFAULT: {...}, sm: {...}, v3: {...}, 'p-spacing': {...} })`
extends `@tailwindcss/typography`'s theme (`tailwind/plugin.js`). `prose` and
`prose-v3` are **safelisted** in `tailwind/preset.js` (`safelist: ['prose', 'prose-v3']`)
because the editor applies them via a computed string the JIT content scanner
can miss. `prose-v3` is the current rich-text style (zero paragraph margins —
spacing is user-controlled via empty paragraphs on an 8px grid, `--tw-prose-*`
vars retuned to the `ink-*` tokens); `prose-p-spacing` is a compatibility
modifier that restores paragraph margins for pre-`prose-v3` content
(`prose prose-v3 prose-p-spacing`). Base font size of `prose-v3` content is
overridable per-instance via the `--prose-font-size` CSS var (default `15px`).

## Dark mode

`darkMode: ['selector', '[data-theme="dark"]']` — set `data-theme="dark"` on
`<html>` to flip every semantic color token and the elevation/focus CSS vars.
`src/utils/theme.ts` exports `useTheme()`: a module-scoped singleton
(`currentTheme: Ref<'light'|'dark'|'system'>`) with `setTheme`, `toggleTheme`,
and `initializeTheme` (reads/writes `localStorage['theme']`, and for
`'system'` tracks `prefers-color-scheme` live via a `matchMedia` listener).
Calling `useTheme()` anywhere lazily runs `ensureInitialized()` once per app
load; every consumer shares the same ref, so a toggle button and a theme
switcher stay in sync automatically. This is the frappe-ui-side equivalent of
Desk's `theme_switcher.js` — same `data-theme` attribute, independent
implementation.

## `data-slot` / `data-state` CSS hooks

frappe-ui components render `data-slot="..."` on their internal parts (e.g.
Combobox: `trigger`, `search`, `input`, `content`, `chevron`, `item`,
`group`, `group-label`, `footer`; Checkbox/CodeEditor: `control`) and
`data-state`/`data-variant`/`data-size`/`data-disabled`/`data-invalid`
attributes reflecting current state (verified across `Combobox.vue`,
`Checkbox.vue`, `CodeEditor.vue`, `ContextMenu.vue`, `DatePicker.vue`,
`DesktopShell.vue`, and their `.cy.ts` specs). Style past a component's prop
surface by targeting these, not internal class names — they're the
documented, stable extension point:

```css
[data-slot="trigger"][data-state="open"] { box-shadow: ...; }
[data-slot="item"][data-disabled] { opacity: .5; }
```

Components deliberately do **not** expose class-injection props
(`triggerClass`, `contentClass`).

## List authoring sugar

`frappe-ui/list` styling hooks are CSS custom properties; the preset adds
matching Tailwind utilities with variant/arbitrary-value support via
`matchUtilities` (`tailwind/plugin.js`):

| Utility | Sets | Scale |
|---|---|---|
| `list-gap-{n}` | `--list-gap` | `theme('spacing')` |
| `list-row-px-{n}` | `--list-row-padding-x` | `theme('spacing')` |
| `list-cols-[...]` | `--list-columns` | arbitrary only (grid-template-columns has no meaningful scale) |

e.g. `max-sm:list-gap-3` instead of hand-writing `max-sm:[--list-gap:0.75rem]`.

## Third-party plugins

The preset also composes `@tailwindcss/forms` and `@tailwindcss/typography`
directly (`tailwind/preset.js` `plugins: [forms, typography, themePlugin, lucideIconsPlugin]`) —
their utilities (`form-input` resets, `prose`) are available without any
extra config in a consuming app.

## Version note (v1 vs 0.1.261 baseline)

Everything on this page is `(v1)` unless marked `(0.1.261 baseline)`.
Not present at the 0.1.261 baseline at all: `lucideIconsPlugin`/`iconPackPlugin`
(icons were `<FeatherIcon>`), the numbered radius scale, `text-{size}-{weight}`
component classes, `.focus-ring-*` utilities + global `:focus-visible` rule
(0.1.x used per-component `focus:ring-2`), `list-gap`/`list-row-px`/`list-cols`
matchUtilities, `prose-v3`/`prose-p-spacing`, the integer `1`–`64` spacing
fill, and the `tailwind/generated/*.json` Figma pipeline (0.1.261's theme
values were hand-authored directly inside `plugin.js`). The 0.1.261
typography scale was smaller (`2xs, xs, sm, base, lg, xl, 2xl, 3xl` plus
`p-*` paragraph variants) and had no `tiny`, `md`, or sizes above `3xl`.
