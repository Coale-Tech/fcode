# DAP Session Panel

**Date:** 2026-10-02  
**Branch:** feat/dap-panel  
**Rows:** parity-matrix §4.3 `debug` tool (partial → surfaced)

## Problem
omp's `debug` tool emits rich structured DAP data (sessions, stack frames,
variables, breakpoints) but Fcode only shows the plain text in tool rows —
no live view of debugger state.

## Solution
A sticky read-only panel below the transcript (same slot as OmpSubagentsList)
that accumulates DAP state from `tool_end` events where `toolName === "debug"`.

No new RPC. No new IPC. No omp changes needed.

## Data flow
```
agentMessage event (IPC.event.agentMessage)
  → type=tool_end, toolName=debug
  → result.details (DebugExecutionDetails):
      snapshot?   → session row
      sessions?   → session rows
      stackFrames?→ frames pane
      variables?  → variables pane
```

## State shape (reducer)
- `sessions: Map<string, DapSessionSnap>` keyed by id
- `frames: DapFrameSnap[]` latest stack_trace result
- `variables: DapVarSnap[]` latest variables result

## UI surface
- Hidden when sessions map is empty.
- Header: "Debug sessions" + active count badge.
- Session rows: status dot · adapter · program (trimmed) · status label.
- Stack section: shows top 10 frames when any session is stopped.
- Variables section: shows up to 20 variables from last query.

## What is skipped
- Breakpoint editor (read-only inspector only).
- Disassembly / memory views (no payload in details).
- Filter by session (only one root session at a time per omp).
